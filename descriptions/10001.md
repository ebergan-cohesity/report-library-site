The job-level detail behind one row of [NBU SQLServer DB Summary]({{ '/reports/report-10000-nbu-sqlserver-db-summary/' | relative_url }}) — every individual backup job for a single client, instance, and database in the selected period, including each job's own status, its parent chain's overall status, and start/finish times. Normally reached by clicking a Summary Status icon on the Summary report rather than run standalone, since the client/instance/database/date-range are passed in from that click.

Note: this report's job-history lookup is scoped strictly to the client and server passed in from the drilldown click, but the hierarchy-walking step it uses internally to resolve each job's parent chain currently scopes on the standard multi-host scope selection instead of that same click-provided client. In practice this hasn't caused incorrect results reported back, but it's a mismatch worth keeping in mind if this report is ever run outside of its normal drilldown path.

**After importing both templates, this one won't be reachable from the Summary report's drilldown until you re-link it** — the Summary's drilldown field points at a SQL Template ID that's assigned by your portal at import time, not the ID baked into this downloaded `.rtd`. See this repo's `ADMIN.md` → "Configuring drilldowns after import" for the exact steps.
